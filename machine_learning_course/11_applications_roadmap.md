# 第 11 章 把它用起来：端到端流水线、负责任的 AI 与进阶路线图

> **本章定位**：这是全课的"回报章"与"地图章"。前十章我们一砖一瓦地造好了机器：从泛化这个中心问题（第 2 章）、线性模型与优化（第 3、4 章）、经典方法与无监督学习（第 5、6 章），到神经网络与深度架构（第 7、8 章）、训练深网络的实战与生成 / 自监督 / 强化学习（第 9、10 章）。但一个会跑模型的人，离一个"能用机器学习解决真实问题、并对后果负责"的人，还隔着一整套**方法论、工程纪律与价值判断**。本章不再引入新算法，而是把散落的零件**串成一条端到端流水线**，给你一套实战智慧，带你巡礼机器学习在各领域的真实落地（兑现本课"通用普适、不限于蛋白质折叠"的承诺），直面负责任 AI 的硬问题，最后把三条暗线做总收束，并交给你一份**进阶路线图**——教材、论文、项目、自学时间表——以及五门课如何配合成一个学习闭环。读完它，你应当从"懂每个零件"升级为"懂整条链路、能判断、能负责、知道下一步往哪走"。

## §11.1 端到端机器学习流水线

### §11.1.1 一个反直觉的开场：模型往往是最不重要的一环

初学者最容易有的错觉是：机器学习 = 选一个厉害的模型 + 调参调到飞起。于是一上来就纠结"用 XGBoost 还是 Transformer""学习率设多少""要不要加一层"。但任何做过真实项目的人都会告诉你一句几乎是行业共识的话：

> **数据与问题定义的质量，通常比模型的选择更能决定项目的成败。**

一个清晰的问题定义 + 干净且有代表性的数据 + 一个朴素的基线模型，几乎总是打败一个模糊的问题 + 脏数据 + 最炫的模型。原因可以用本课的暗线说清：模型再强，也只是在你给定的**数据分布**和**目标**下做拟合（暗线二的"目标 + 优化"）；如果数据本身有偏、问题问错了，那么你优化得越好，错得越自信。机器学习放大数据里的信号，**也放大数据里的偏差与错误**。

打个比方：模型是一台榨汁机，数据是水果。换一台更贵的榨汁机（从随机森林换到 Transformer），能把同一批水果榨得更顺、出汁率高几个百分点；但如果水果本身是烂的（脏数据），或者你其实想要的是果酱而不是果汁（问题定义错了），那么再贵的榨汁机也救不了你。初学者的精力分配常常是"90% 调榨汁机、10% 挑水果"，而成熟从业者恰好反过来。本课前十章给了你各式各样的"榨汁机"，本章要纠正的正是这个精力错配。

所以本节给出的不是"模型动物园"，而是一条**七段式流水线**。它的精神是：把大量精力前移到"问题定义"和"数据"，把模型当成可替换的零件。

```
问题定义 → 数据收集/清洗 → 特征/表示 → 选模型与基线 → 训练 → 评估 → 部署 → 监控/迭代
   ↑__________________________________________________________________________|
                          （这是一个环，不是一条直线）
```

### §11.1.2 第一段：问题定义（problem framing）

这是回报最高、最常被跳过的一段。要回答的问题包括：

- **这到底是不是一个机器学习问题？** 如果规则清晰、可枚举（如"金额 > 10000 就标记复核"），写规则比训模型更可靠、更可解释、更便宜。机器学习适合"规则难以手写、但有大量带标签数据可学"的场景。
- **它是什么类型的学习问题？** 监督（有标签）/ 无监督（无标签找结构）/ 自监督（从数据本身造标签）/ 强化（与环境交互、延迟奖励）——这决定了你后面几乎所有选择（回扣第 2、6、10 章）。
- **预测目标（target）是什么？标签从哪来、可靠吗？** "预测用户是否会流失"——流失怎么定义？30 天不登录算吗？标签是人工标注、日志推断、还是业务规则？标签噪声会成为你模型精度的天花板。
- **用什么衡量成功？** 必须同时定义**机器学习指标**（如 AUC、F1）和**业务指标**（如挽回的收入、减少的人工复核时长），并想清楚二者如何对齐（§11.2 详谈）。
- **有哪些约束？** 延迟（实时还是离线）、可解释性（信贷 / 医疗常被法规要求可解释）、公平性、隐私、算力 / 成本预算。这些约束会反过来限定你能用什么模型。

把这些问题想清楚，常常会改变整个项目的形态。一个经典的转向是：业务方说"我要预测每个用户的流失概率"，但深聊后发现他们真正想做的是"把有限的客服资源优先分配给最该挽留的人"——这其实是一个**排序 / 资源分配**问题，而不是精确的概率预测问题。两者的目标、指标、甚至是否需要机器学习都不同。**问题定义阶段花一天，往往能省下后面一个月的白干。**

> **常见陷阱**：把"提升模型 AUC"当成项目目标。AUC 提升了 0.02，业务却毫无变化的项目比比皆是——因为没人问过"AUC 和我们真正想改善的东西是什么关系"。**先定义业务上的成功，再倒推机器学习指标，最后才选模型。**

> **给数学 / CS 读者的视角**：问题定义之于机器学习，就像**需求分析 / 接口设计**之于软件工程。你不会在没想清楚要解决什么问题、输入输出契约是什么之前就开始写核心算法——那叫"过早优化"。机器学习里"过早建模"同样是大忌：先把"输入是什么、输出是什么、用什么标准判定成功、有什么约束"这份契约定死，模型才是后面可替换的实现细节。

### §11.1.3 第二段：数据收集与清洗（data collection & cleaning）

经验上，真实项目里**数据相关的工作常占据大部分时间**。要做的事包括：

- **收集与整合**：从数据库、日志、第三方、传感器、爬虫等汇集；处理多源数据的对齐与去重。
- **清洗**：缺失值（删除？均值 / 中位数填充？模型预测填充？还是把"缺失"本身当一个有信息的类别？）、异常值、重复、单位 / 格式不一致、标签错误。
- **理解数据**：探索性数据分析（exploratory data analysis, EDA）——画分布、看相关、查类别不平衡、找泄漏线索。这一步直接呼应《概率与统计》第 3 章（期望 / 矩）与可视化直觉。
- **划分数据集**：训练 / 验证 / 测试三分（回扣第 2 章模型选择）。**划分必须在任何"看数据做决定"之前完成**，否则信息会从测试集泄漏进来。

关于缺失值，再多说一句，因为它最能体现"数据决策即建模决策"。把缺失粗暴地用 0 或均值填掉，等于偷偷假设了"缺失是随机的、和标签无关"——但现实里缺失常常**自带信息**：一个用户没填收入，可能恰恰和他的信用风险相关。这时把"是否缺失"单独做成一个二值特征，往往比任何填充都更有效。**每一个清洗决策，都是一个被悄悄做掉的建模假设**，要有意识地做、而不是用默认值蒙混过去。

> **常见陷阱（数据泄漏 data leakage，实战头号杀手）**：用了在预测时刻**不该拥有的信息**。典型案例：(1) **用了未来信息**——预测今天是否下雨时，特征里混进了"今天的实际降雨量"；(2) **标签泄漏**——预测是否患病，特征里有"是否在用治疗该病的药"；(3) **预处理泄漏**——在划分训练 / 测试之前，用**全体数据**算了均值 / 方差做标准化，或做了特征选择，于是测试集的信息偷偷进了训练。泄漏的症状是：离线指标好得不真实，上线后一塌糊涂。**铁律：所有"从数据里学到的东西"（缩放参数、填充值、特征选择、编码表）都只能用训练集拟合，再应用到验证 / 测试集。** sklearn 的 `Pipeline` 就是为强制这条纪律而生。

> **诚实的边界**：再强大的模型也无法弥补"数据没有覆盖你要预测的情形"。如果训练数据里某类样本极少（罕见病、长尾用户、新出现的攻击模式），模型在那里的表现就是不可信的——这不是调参能救的，这是采样的局限。承认"我的数据没说话的地方，我的模型也不该说话"，是负责任的起点（呼应 §11.4 分布漂移）。

### §11.1.4 第三段：特征与表示（features & representation）

这一段是经典机器学习与深度学习分野最大的地方，也是暗线二"表示"格的直接体现。

- **经典路线——特征工程（feature engineering）**：人来设计特征。把日期拆成"星期几 / 是否节假日"、把文本变成 TF-IDF、把类别变量做独热 / 目标编码、构造交互项与比率、做标准化 / 归一化。在**表格数据**上，好的特征工程往往比换模型更有效。
- **深度路线——表示学习（representation learning）**：让模型从原始数据（像素、字符、波形）**自动学出**特征（回扣第 6、8 章）。这在图像、文本、语音上压倒性地胜过手工特征——因为这些数据的好特征人类很难手写。
- **何时用哪条？** 一个粗略但好用的判据：**数据有强的、已知的结构（网格 / 序列 / 图）且量大 → 表示学习；数据是异构表格、量中等、可解释性重要 → 特征工程 + 经典模型**（§11.2 详谈）。

值得强调的是，深度学习"自动学特征"并不意味着特征工程消亡了，而是它的形态变了：在深度时代，"特征工程"很大程度上变成了**架构设计**（用 CNN 还是 Transformer，等于决定了模型先天会抽什么样的特征，回扣第 8 章）和**数据增强 / 自监督预训练**（用什么辅助任务逼模型学出好表示，回扣第 9、10 章）。所以表示这一格的功夫永远在，只是从"手搓特征"上移到了"设计让模型自己搓出好特征的机制"。

> **与数学三课的连接**：特征 / 表示本质上是一个**坐标变换**——把数据从"原始坐标"映到"任务更易解的坐标"。标准化是平移 + 缩放，PCA 是找方差最大的正交方向（《线性代数》第 8 章 SVD/PCA），嵌入是把离散符号映到稠密向量空间（第 8 章）。"选对表示" = "选对坐标系"，这是贯穿线代与本课的同一个几何直觉：在一个坐标系里纠缠难分的数据，换个坐标系可能线性可分。

### §11.1.5 第四段：选模型与基线（model & baseline）

**先建一个强基线（strong baseline），是本节最重要的一条工程纪律**，§11.2.1 会专门展开方法论层面的"为什么"。这里先讲清它在流水线里的位置、为什么必须前置，以及怎么从基线一步步往上选模型。

**为什么"基线先于一切"是工程后果而非洁癖。** 在流水线里，选模型这一段如果跳过基线、直接上复杂模型，会留下三个具体的工程债：(1) **没有分母**——你报出的 0.88 准确率没人知道好坏，可能多数类就占 0.88，复杂模型其实学了个寂寞（§11.2.1）；(2) **基础设施未经压力测试**——数据管道、评估脚本、训练 / 测试划分这些"管道工程"如果在复杂模型阶段才第一次跑，bug 会和模型问题缠在一起，调试成本翻倍；先用一个 30 秒就能训完的逻辑回归把整条管道跑通，等于先做了一次廉价的"系统冒烟测试"；(3) **归因失效**——后面每加一个花哨组件，你都说不清提升是来自这个组件还是来自某个一并改掉的预处理。所以基线不是"先做个简单的应付一下"，而是给后续所有决策提供**参照系与干净地基**的必需品。

**从基线到选型的决策树（先按任务类型框定候选族，再按数据结构收窄）。** 模型选择不是"挑最强的"，而是顺着一棵树往下走：

```
任务是什么？
├─ 监督 · 分类 / 回归
│    └─ 数据结构是什么？（这一步决定归纳偏置，详见 §11.2.4）
│         ├─ 异构表格（数值+类别）         → 平凡基线 → 逻辑回归/线性 → GBDT（多半到此为止）
│         ├─ 图像 / 网格                   → 小预训练 CNN 微调 → 视需要换更大模型/ViT
│         ├─ 文本 / 序列                   → 预训练语言模型微调 → 视需要上更大模型
│         └─ 有序时序                       → 经典（ARIMA/指数平滑）/ GBDT 喂时序特征 → RNN/Transformer
├─ 无监督 · 找结构 / 降维 / 聚类           → K-means / PCA 起步（第 6 章）
└─ 强化 · 与环境交互、延迟奖励             → 先确认真的需要 RL（第 10 章），多数"序列决策"可被监督近似
```

这棵树的精神是：**任务类型决定大方向，数据结构决定具体架构，而每一层都从该层最简单的基线起步。** 例如同样是"分类"，表格走 GBDT 线、图像走 CNN 线，分岔点是数据结构而非任务名（这正是 §11.2.4 要展开的归纳偏置判据）。

**复杂度 / 收益比：每往上爬一级都要付的"过路费"。** 建基线的顺序是"由弱到强"——先**平凡基线**（永远猜多数类 / 均值）给绝对下限，再**简单模型基线**（逻辑回归 / GBDT）给"省事方法的天花板"，最后才考虑更复杂的模型。每往上爬一级，你都要能回答：**这一级的额外复杂度（更难调、更慢、更吃数据、更不可解释、上线 / 运维更重），换来的指标提升值不值？** 举个具体的例子：在一个表格风控任务上，逻辑回归给 0.80 AUC，GBDT 给 0.86（值得，提升明显且 GBDT 仍可解释、好部署），而一个调了两周的深度模型给 0.865——这 0.005 多半**不值**：它换来 10 倍的训练成本、更难的上线、丢掉的特征重要性可解释性，在风控的可解释法规约束下尤其是亏本买卖。**收益要按业务价值折算、成本要把训练 + 推理 + 运维 + 可解释性 + 风险全算进去**，这个比值（而不是单看指标）才是选型的真正标尺。这也呼应 §11.4.7："更大更强"从不是免费的。

### §11.1.6 第五段：训练（training）

训练阶段的工程要点（多在第 4、9 章已详述，这里做流水线视角的串联）：

- **可复现性（reproducibility）**：固定随机种子、记录数据版本 / 代码版本 / 超参数 / 环境。"上周那个 0.92 的模型怎么复现不出来了"是真实的痛，根因往往是某处没固定的随机性或悄悄变了的数据。
- **从小做起，先过拟合给自己看**：拿一小撮数据（几十个样本）、关掉正则，看模型能否把训练误差压到近 0。如果连这都做不到，说明是代码 / 数据 bug 或优化没跑通，而不是模型容量不够（第 9 章调试智慧）。这是性价比极高的"冒烟测试"。
- **超参数搜索（hyperparameter search）**：网格搜索 / 随机搜索 / 贝叶斯优化，**只在验证集上调**（回扣第 2 章）。随机搜索常比网格搜索更高效，因为它不会把预算浪费在不敏感的维度上。
- **实验管理**：用工具（如实验追踪平台）记录每次跑的配置与结果，否则几十个实验之后你会彻底迷失"到底是哪个改动带来了提升"。

> **常见陷阱（用测试集调参）**：把"在验证集上选超参"和"在测试集上报性能"搞混。一旦你根据测试集的表现去改任何东西（选模型、调参、加特征），测试集就被"污染"了——它不再能给出对未见数据的无偏估计，你又一次把信息从测试集泄漏了回来。**测试集是一次性的、最后才用的、用完就该警惕"我是不是开始照着它优化了"。** 这是第 2 章模型选择纪律在流水线里的硬性落地。

### §11.1.7 第六段：评估（evaluation）

评估不是"跑一个准确率数字"，而是一套**回答"它到底好不好、对谁好、在哪失败"**的方法论，§11.2.3 专门展开指标选择。流水线层面要强调三件事：

- **评估必须用从未参与任何决策的测试集**，且其分布要尽量贴近部署时的真实分布——如果线上面对的是新地区 / 新时间段的数据，用一个和线上分布脱节的测试集报出的数字是自欺欺人（直通 §11.4 分布漂移）。
- **分群评估（slice-based evaluation）**：不只看整体指标，要按子群体（不同地区 / 设备 / 人群 / 时间段）分别看——整体高准确率可能掩盖某个子群的灾难（直通 §11.4 公平性）。一个对多数群体很好、对少数群体很差的模型，其整体指标会被多数群体"平均掉"而显得很好。算个小例子看这种"平均障眼法"有多狠：设多数群体占 90%、准确率 95%，少数群体占 10%、准确率只有 60%，则整体准确率 $=0.9\times0.95+0.1\times0.60=0.915$——**91.5% 看上去相当体面，却完全藏住了对少数群体每 10 个就错 4 个的系统性失败**。如果这个少数群体恰是某个受保护人群（如某地区用户、某年龄段），这就不只是性能问题、更是公平问题。分群评估就是把这个加权平均拆开看，不让多数群体替少数群体的失败"背书"。
- **错误分析（error analysis）**：人工翻看一批被模型搞错的样本，把错误归类。这是性价比极高却最常被偷懒跳过的一步——它常常比再调十次参数更能告诉你下一步该做什么。一个可操作的最小流程：(1) 从验证集（不是测试集！）里**抽 50–100 个错样本**，最好分层抽（各类别 / 各置信度段都抽到）；(2) 逐个看，给每个错误**打标签归类**——是"标签本身就标错了"（数据质量问题）、"某类输入系统性出错"（如所有夜间图片都错 → 数据覆盖 / 增强问题）、"模型抄了捷径"（如靠背景而非主体判断 → §11.4.2）、还是"确实是难样本"（人也难判）；(3) **统计各类占比**，按占比决定下一步——如果 40% 的错来自标签噪声，那该去清数据而不是调模型；如果 40% 来自某个子群，那该去补该子群的数据。这一步把"模型为什么错"从玄学变成可统计、可行动的工程问题。

### §11.1.8 第七段：部署、监控与迭代（deployment, monitoring & MLOps）

模型上线**不是终点，是另一个起点**。这一段统称 **MLOps（machine learning operations）**——把机器学习系统当成需要长期运维的软件系统。

- **部署形态**：批量预测（离线跑完写库）、在线服务（实时 API）、边缘 / 端上（手机 / 嵌入式，受算力与功耗约束）。

一个真实的线上机器学习系统，远不止"一个模型文件"。它的核心组件大致如下，恰好与开篇的流水线环呼应（线下训练 → 线上服务 → 监控 → 反馈 → 回到训练）：

```
          ┌──────────────────────────────────────────────────────────┐
          │                     线下（训练侧）                          │
   原始数据 → 特征管道 ──► 特征存储 ──► 训练 ──► 模型仓库（带版本）        │
          │   (同一套逻辑)      ▲                        │                │
          └────────────────────┼────────────────────────┼──────────────┘
                               │ 同一套特征逻辑           │ 灰度/影子发布
          ┌────────────────────┼────────────────────────▼──────────────┐
          │                     线上（服务侧）                          │
   线上请求 → 特征管道 ──► 特征存储 ──► 模型服务 ──► 预测                 │
          │                                  │                          │
          │                                  ▼                          │
          │                          监控（输入分布/预测分布/线上指标）  │
          └──────────────────────────────────┬──────────────────────────┘
                                             │ 漂移/掉点告警
                          反馈与真值回流 ──────┘──► 触发重训（回到线下）
```

围绕这张图，MLOps 的几个核心实践值得单独说清：

- **训练 / 服务一致性（training-serving skew）与特征存储（feature store）**：训练时的特征计算逻辑，必须和线上服务时**一模一样**——否则线上特征和训练特征不是同一个东西，模型表现会莫名其妙地差。最隐蔽的一种 skew 是"线下能用全量历史算的特征（如用户近 30 天消费总额），线上要在毫秒内实时算出来"，两边稍有口径差异（时区、截断时刻、缺失处理）就埋雷。**特征存储**就是为治这个病而生：它让线下训练和线上服务**共享同一份特征定义与同一套计算代码**，线下从中取历史特征训练、线上从中取实时特征服务，从架构上消灭 skew。
- **数据与模型版本化（data & model versioning）**：要能回答"这个上线的模型，是用哪一版数据、哪一版代码、哪一组超参训出来的"。代码用 Git，**数据和模型也要有自己的版本号**（数据快照、模型仓库 + 元数据）。否则 §11.1.6 那句"上周 0.92 的模型怎么复现不出来了"会反复折磨你，出事时也无法追溯与回滚。
- **渐进发布：影子 / 灰度 / 回滚（shadow / canary / rollback）**：新模型绝不"一把梭"全量上线。**影子部署（shadow）**让新模型和老模型同时收线上流量、但只有老模型的预测真正生效，新模型的预测只记录不影响用户——用来在真实流量上对比两者而零风险。**灰度 / 金丝雀（canary）**只把一小部分流量（如 1%、5%）切给新模型，盯紧指标没问题再逐步放大。一旦监控告警，**回滚（rollback）**到上一个已知良好版本——这正是数据 / 模型版本化的回报。这套"小步快跑、随时可退"的纪律，和软件工程的灰度发布是同一个智慧。
- **监控（monitoring）**：监控**输入数据分布**（有没有漂移）、**预测分布**（模型输出的统计量有没有突变，这是真值还没回流时最早的预警信号）、以及（如果能拿到真值）**线上指标**。这是 §11.4 分布漂移在工程上的落地。
- **反馈回路与迭代**：收集线上反馈 → 发现新的失败模式 / 漂移 → 回到问题定义或数据 → 重训 / 改模型。**整条流水线是一个环。** 还要警惕**反馈回路本身造成的偏差**：推荐系统只推它认为你喜欢的，于是只收集到这些的反馈，数据越来越窄（§11.4 详谈）。

> **给数学 / CS 读者的视角**：MLOps 之于机器学习，约等于 DevOps / CI-CD 之于软件——只不过它要同时给**代码、数据、模型**三样东西做版本化、测试与发布，而数据和模型还会"自己漂移变质"，所以多了软件世界没有的"监控分布漂移 + 定期重训"这一环。把模型当成"训完就完事的产物"，正如把上线当成软件的终点一样，是经验不足的标志。

> **实战连接（推荐系统）**：一个新闻推荐系统上线第一天 AUC 很高，三个月后悄悄变差。监控发现：用户兴趣随热点漂移（数据漂移），且系统只推它打高分的内容、从不试探新内容，反馈数据越来越同质（反馈回路偏差），模型困在自己造的"信息茧房"里。修复靠的不是换模型，而是**引入探索（呼应第 10 章强化学习的探索 vs 利用）+ 持续重训 + 漂移监控 + 灰度验证**——这正是 MLOps 的价值。

> **要点**：端到端流水线 = 问题定义 → 数据 → 特征 / 表示 → 模型与基线 → 训练 → 评估 → 部署 → 监控 / 迭代，且是一个**环**。其中**问题定义与数据通常比模型选择更决定成败**；数据泄漏与训练 / 服务不一致是头号实战杀手；模型上线只是另一个起点，MLOps 让系统长期可信。

## §11.2 实战智慧与方法论

如果说 §11.1 是流水线的"骨架"，本节就是填进去的"肌肉"——一组能让你少走弯路、做出正确判断的经验法则。它们大多是前几章原理的实战投影。

### §11.2.1 先建强基线：方法论的第一性原理

**强基线（strong baseline）** 是你做任何机器学习项目都应先做的事。它有两层：

1. **平凡基线（trivial baseline）**：分类就预测多数类，回归就预测均值 / 中位数。它给你一个"什么都不学能做到多好"的下限。如果你的"复杂模型"还不如永远猜多数类，那它学到的是负价值。
2. **简单模型基线（simple model baseline）**：表格 / 一般任务上用**逻辑回归（logistic regression）或梯度提升树（gradient boosting decision trees, GBDT）**；图像 / 文本上用一个小的预训练模型微调。它给你一个"用最省事、最稳的方法能做到多好"的参照。

为什么强基线如此重要？因为机器学习的全部价值在于**相对提升**，而你需要一个分母。没有基线，0.91 的准确率毫无意义——多数类是不是就占 91%？此外，建基线的过程会逼你**先把数据管道、评估、划分全部跑通**，把脏活在简单模型阶段就清掉，等你上复杂模型时基础设施已经稳了。

> **给数学 / CS 读者的视角**：建基线就像写代码先写出一个能跑通的朴素版本（brute force），再考虑优化。你不会一上来就写一个高度优化的算法而不确认它解的是对的问题。机器学习里的"先朴素后优化"是同一个工程智慧——只不过这里的"正确性"由泛化与业务指标定义，而不是单元测试。

### §11.2.2 调试顺序：当模型不工作时

模型表现不好时，按这个**由近及远**的顺序排查（综合第 4、9 章）：

1. **数据 / 标签对吗？** 看几十个样本和标签，确认你以为的输入输出和实际一致。大量"模型不行"其实是"数据 / 标签错了"。
2. **能过拟合一小撮数据吗？** 拿 50 个样本，关掉正则，看模型能否把训练误差压到近 0。**不能 → 是 bug 或容量 / 优化问题**（模型连记都记不住）；**能 → 模型 + 优化基本没问题，问题在泛化**，往下走。
3. **是欠拟合还是过拟合？** 看训练误差 vs 验证误差的差距（§11.2.5 的诊断表）。
4. **优化在收敛吗？** 看损失曲线：是否下降、是否震荡 / 发散（学习率问题，回扣第 4 章）、是否过早平台（梯度消失 / 学习率太小，回扣第 7、9 章）。
5. **超参数与正则是否合理？** 在已确认前面都对之后，再调学习率、正则强度、容量。

> **常见陷阱**：一上来就疯狂调超参数，却没确认数据和损失曲线。这等于在地基没问题之前就疯狂装修。**调试要从"最可能且最便宜的错误"（数据 / 标签 / 泄漏）查起，而不是从"最高级的旋钮"（架构 / 学习率）查起。**

### §11.2.3 评估指标的选择：准确率的陷阱与一整套替代

评估指标是机器学习里最容易出错、后果最严重的判断之一（守住总纲正确性红线）。

**准确率（accuracy）的陷阱——类别不平衡**。设一个病在人群中患病率 1%。一个永远预测"没病"的模型，准确率高达 99%，却**毫无用处**（漏掉了所有病人）。准确率在类别不平衡时具有极强的误导性。

对二分类，把预测和真值列成**混淆矩阵（confusion matrix）**：真阳 TP、假阳 FP、真阴 TN、假阴 FN。由此定义：

$$
\text{精确率（precision）} = \frac{TP}{TP+FP}, \qquad
\text{召回率（recall）} = \frac{TP}{TP+FN}.
$$

- **精确率**回答"我说是阳性的，有多少真是阳性"（关心**误报代价**，如垃圾邮件——把正常邮件判成垃圾很烦）。
- **召回率**回答"所有真阳性里，我抓到了多少"（关心**漏报代价**，如癌症筛查、欺诈检测——漏掉一个后果严重）。

二者通常此消彼长（调阈值，一个升另一个降）。综合二者用 **F1 分数**——精确率与召回率的调和平均：

$$
F_1 = \frac{2\cdot \text{precision}\cdot \text{recall}}{\text{precision}+\text{recall}}.
$$

调和平均的妙处：只要有一个很低，$F_1$ 就被拉低，逼你**两者都不能太差**。

不想固定一个阈值时，用**阈值无关**的曲线指标：

- **ROC 曲线与 AUC（area under the ROC curve）**：横轴假阳率、纵轴真阳率，扫遍所有阈值。AUC 的概率含义很美：**随机取一个正样本和一个负样本，模型给正样本打分更高的概率**。AUC=0.5 是瞎猜，1.0 是完美。这个含义可以两行看明白：把所有"正-负"样本对排开，AUC = 模型给正样本打分高于负样本的样本对所占比例（打分相等记半分）——它正是 Mann–Whitney U 统计量的归一化，所以"曲线下面积"和"排序正确率"是同一回事。但在**极度不平衡**时 ROC-AUC 会偏乐观（大量真阴让假阳率显得很小），此时更该看 **PR-AUC**（precision-recall 曲线下面积）。注意：PR 曲线 / PR-AUC 只看正类（少数类）、对它更敏感，且**随正类基率变化**——同一个模型在正类更稀少的数据集上 PR-AUC 会更低，因此 PR-AUC 适合在固定数据集内比较模型，不宜当作可跨数据集直接比较的绝对值。

**回归的指标**：

$$
\text{MSE} = \frac1n\sum (y_i-\hat y_i)^2,\quad
\text{MAE} = \frac1n\sum |y_i-\hat y_i|,\quad
R^2 = 1 - \frac{\sum(y_i-\hat y_i)^2}{\sum(y_i-\bar y)^2}.
$$

MSE 对大误差惩罚重（平方）、对离群点敏感；MAE 更鲁棒。$R^2$（决定系数）的含义是"模型比'永远预测均值'这个平凡基线好多少"：$R^2=1$ 完美、$R^2=0$ 等于平凡基线、$R^2<0$ 比平凡基线还差（这是会发生的！）——$R^2$ 把 §11.2.1 的"强基线思想"直接写进了指标。

> **概率视角**：MSE 是高斯噪声下的负对数似然，MAE 是拉普拉斯噪声下的负对数似然（回扣第 3 章 MLE-损失对应、《概率与统计》第 7 章）。所以"选 MSE 还是 MAE"本质是"你假设噪声是高斯还是更重尾的拉普拉斯"——这是一个被悄悄做掉的建模假设，不是任意的偏好。

> **常见陷阱（指标与业务脱节）**：盯着一个机器学习指标优化，却没问它和业务目标的关系。例子：欺诈检测把召回率刷到 99%，但精确率掉到 5%——意味着每抓一个真欺诈要误伤 19 个正常用户去人工核查，运营成本爆炸。**正确做法是把误报 / 漏报的真实代价量化（如每个 FP 损失 X 元、每个 FN 损失 Y 元），用加权代价或在 PR 曲线上选业务最优的工作点，而不是迷信单一指标。**

### §11.2.4 何时用经典方法 vs 深度学习：回扣归纳偏置

这是初学者最纠结、也最该想清楚的判断。答案不是"深度学习总更强"，而是**看数据结构与归纳偏置是否对得上**（暗线三）。

| 维度 | 倾向**经典方法**（GBDT / 线性 / SVM） | 倾向**深度学习** |
|---|---|---|
| 数据类型 | **异构表格**（数值 + 类别混合） | 图像 / 文本 / 语音 / 图（有网格 / 序列 / 图结构） |
| 数据量 | 小到中等（几千~几十万行） | 大（数十万~海量） |
| 结构 / 对称性 | 几乎没有可利用的对称性 | 有强对称性（平移 / 时序 / 置换）可焊进架构 |
| 可解释性需求 | 高（信贷 / 医疗，要给理由） | 低或可后处理解释 |
| 算力 / 工程预算 | 有限、要快上线 | 充足、能承受训练成本 |

**为什么表格数据上 GBDT 至今常打败深度网络？**（回扣第 5、8 章）表格的列之间没有空间 / 时序 / 图结构，深度架构那些精妙的归纳偏置（平移等变、局部性）**在这里无用甚至有害**——你强行假设的对称性数据里根本不存在。而决策树的"轴对齐分段常数"偏置恰好契合表格里"某个特征超过某阈值就如何"的逻辑。**强偏置对上了是福，对不上是祸——没有免费的午餐。**

> **实战连接（科学计算 / 蛋白质折叠）**：AlphaFold 之所以用 Transformer + 几何深度学习而不是 GBDT，正是因为蛋白质数据**有结构**——序列是序列、空间是三维几何、共进化是关系型结构，这些对称性可以、也应该被焊进架构（呼应第 8 章、《蛋白质折叠》第 7 章）。而同样是科学问题，如果你要预测的是一张"实验条件→产率"的异构表格，GBDT 很可能更合适。**领域不决定方法，数据结构才决定方法。**

### §11.2.5 过拟合 / 欠拟合的诊断与对策清单

这是暗线一（泛化）的实战收束（回扣第 2、9 章）。诊断靠**训练误差与验证误差的关系**：

| 症状 | 训练误差 | 验证误差 | 诊断 | 本质 |
|---|---|---|---|---|
| 都高 | 高 | 高（≈训练） | **欠拟合 / 高偏差** | 容量不够 / 没学到 / 优化没到位 |
| 训练低、验证高 | 低 | 高（差距大） | **过拟合 / 高方差** | 记住了训练集、没泛化 |
| 都低且接近 | 低 | 低 | **刚好** | 偏差 - 方差平衡较好 |

**对策清单**：

- **欠拟合（高偏差）**：增加模型容量（更深 / 更宽 / 更强模型）、减弱正则、加更多 / 更好的特征、训练更久 / 调好优化（先确认损失真的收敛了）。
- **过拟合（高方差）**：**加数据**（最根本，可用数据增强）、加正则（L2/L1、Dropout、早停——回扣第 9 章）、减小容量、用更强归纳偏置（暗线三）、集成（回扣第 5 章）。

> **诚实的边界（双下降 double descent，本课最反直觉处）**：上面"参数越多越易过拟合"的经典图景，在现代过参数化深度网络里**会被打破**。当模型容量越过"刚好插值训练集"的临界点继续增大，测试误差可能**先升后再降**（双下降），最终在巨大模型处反而泛化得更好（回扣第 2、9 章暗线一的高峰）。所以**"参数多 = 过拟合"不是铁律**；它在经典容量区间成立，在过参数化区间失效。这正是泛化理论至今未完全讲清的前沿——诚实地说，我们对"为什么大模型泛化好"只有部分理解。

> **要点**：先建强基线再谈提升；调试从数据 / 标签 / 泄漏查起、用"能否过拟合一小撮"区分 bug 与泛化问题；指标按业务代价选（准确率在不平衡时骗人，看精确率 / 召回 / F1 / AUC / PR-AUC，回归看 MAE/MSE/$R^2$）；经典 vs 深度由数据结构与归纳偏置是否对得上决定；过拟合 / 欠拟合靠训练 - 验证误差关系诊断，但"参数多必过拟合"被双下降证伪。

## §11.3 跨领域应用巡礼

本节兑现本课的核心承诺：**机器学习是通用普适的方法论，不属于任何单一领域。** 下面平级地巡礼七个领域，每个都点明它主要利用**哪种归纳偏置 / 架构**，让你看到第 8 章"架构 = 焊进去的对称性"如何在各领域兑现。蛋白质折叠在此作为"科学计算"里最闪亮的一例出场，与视觉 / NLP / 推荐**平级**。

下面这张表是本节的鸟瞰图：

| 领域 | 代表任务 | 数据结构 | 主用归纳偏置 / 架构 |
|---|---|---|---|
| 计算机视觉 | 分类 / 检测 / 分割 | 网格（像素） | 平移等变 / 局部性 → **CNN**；近年 **ViT** |
| 自然语言处理 | 分类 / 翻译 / 大模型 | 序列（token） | 关系型 + 长程依赖 → **Transformer** |
| 语音 | 识别 / 合成 | 时序波形 / 频谱 | 时序 + 局部 → **CNN/RNN/Transformer** |
| 推荐系统 | 点击 / 评分预测 | 用户 - 物品交互 | 低秩 / 相似度 → **嵌入 + 矩阵分解 / 深度** |
| 时间序列 | 预测 / 异常检测 | 有序时序 | 时序结构 → **经典 / RNN / Temporal-CNN / Transformer** |
| 表格 / 风控 | 评分 / 欺诈 | 异构表格 | 轴对齐分段 → **GBDT / 线性**（深度常落败） |
| 科学计算 | 折叠 / 分子生成 | 序列 + 几何 + 图 | 几何 / 置换等变 → **Transformer + 几何深度学习 / 扩散** |

### §11.3.1 计算机视觉（computer vision）

三大经典任务呈"由粗到细"的阶梯：**分类**（图里是什么）→ **目标检测**（什么 + 在哪，画框）→ **语义 / 实例分割**（每个像素属于什么）。主导归纳偏置是**平移等变 + 局部性**，自然落到 **CNN**（回扣第 8 章）：物体在图里平移，识别结果不该变；局部像素相关性强。近年 **ViT（Vision Transformer）** 把图切成小块当 token 喂 Transformer，用大数据 + 弱偏置换来更强表达——这正是第 8 章"强偏置省数据、弱偏置靠数据"权衡的活例。

### §11.3.2 自然语言处理（natural language processing, NLP）

任务谱系：文本分类（情感 / 主题）→ 序列标注（命名实体）→ 机器翻译（序列到序列）→ **大语言模型（large language model, LLM）**。语言是**序列**，关键是**长程依赖**与**关系型结构**（谁修饰谁、指代谁），这正是**注意力 / Transformer** 的主场（回扣第 8、10 章）。LLM 的范式是：在海量文本上做**自监督**的下一个词预测（自回归语言建模，回扣第 10 章），学到通用语言表示，再微调 / 提示到下游任务——一个模型，万般用途，这是"基础模型（foundation model）"范式的代表。

> **与数学三课的连接**：语言模型预测下一个词，训练目标是**交叉熵 = 负对数似然（NLL）**（《信息论》第 3、4 章 + 《概率与统计》第 7 章）；困惑度（perplexity）= $\exp(\text{交叉熵})$，是信息论压缩视角下"模型对语言的平均不确定性"，越低说明模型把语言"压"得越好。注意底数要和交叉熵的对数底一致：机器学习里 NLL 几乎总用自然对数（单位 nats），此时困惑度 $=e^{H}$；只有当交叉熵以 bit（$\log_2$）计时，困惑度才是 $2^{H}$。**会说话的模型，本质是个好的语言压缩器**——这把 NLP 直接接回了信息论。

### §11.3.3 语音（speech）

语音识别（speech-to-text）、语音合成（text-to-speech）、说话人识别。原始数据是**一维时序波形**，通常先转成时频谱（一种"图像"）。归纳偏置是**时序 + 局部模式**，历史上用 CNN（在谱图上）、RNN（建时序），现在也大量用 Transformer。语音是个好提醒：**同一份数据可以有多种表示**（波形 vs 谱图），选哪种表示就是选哪种归纳偏置（暗线二 / 三）。

### §11.3.4 推荐系统（recommender systems）

预测"用户会不会点 / 喜不喜欢物品"。核心数据是稀疏的**用户 - 物品交互矩阵**。经典方法是**矩阵分解（matrix factorization）**：把交互矩阵近似成两个低秩矩阵之积，每个用户 / 物品得到一个**嵌入向量**，预测 = 两向量内积。

> **与数学三课的连接**：矩阵分解就是《线性代数》第 8 章**低秩近似 / SVD** 的直接应用——假设"用户偏好由少数潜在因子（口味维度）决定"就是一个低秩假设（归纳偏置）。"相似度 = 内积"又回到《线性代数》第 4 章内积的几何（也呼应第 8 章嵌入）。深度推荐在此之上叠加神经网络建模高阶交互，但低秩 + 嵌入的内核没变。现代检索把它做成"最大内积搜索"，让系统扩展到上亿物品。

### §11.3.5 时间序列与预测（time series & forecasting）

需求预测、股价、传感器、能耗。数据是**有序的时序**，归纳偏置是时序结构（趋势 / 季节 / 自相关）。这里**经典方法仍然非常能打**：ARIMA、指数平滑、以及把时序特征喂给 GBDT，常在中小数据上胜过深度模型。深度路线用 RNN/LSTM、时序卷积、或 Transformer 变体。时间序列也是**数据泄漏的重灾区**：划分训练 / 测试必须**按时间切**（用过去预测未来），绝不能随机打乱——否则用未来预测过去，离线指标好得离谱、上线全废。

### §11.3.6 表格数据与风控（tabular data & risk control）

信用评分、欺诈检测、流失预测、保险定价。数据是**异构表格**，归纳偏置是"轴对齐的分段规则"，**GBDT 与逻辑回归至今是主力**（回扣 §11.2.4、第 5 章）。风控领域还有强的**可解释性与公平性**约束（法规常要求能向用户解释拒贷理由），这进一步偏向可解释模型，或要求对深度模型做事后解释（§11.4）。

### §11.3.7 科学计算：旗舰例子（scientific computing）

机器学习正在重塑科学。两个旗舰例子：

- **蛋白质折叠（protein folding）—— AlphaFold**：从氨基酸序列预测三维结构，被视为深度学习在科学上的里程碑之一。它的核心是 **Transformer 类注意力 + 几何深度学习（geometric deep learning）**：用注意力建模序列内 / 序列间（多序列比对中的共进化）的关系，用对**三维旋转 / 平移等变**的几何模块直接在结构空间里推理（回扣第 8 章、《线性代数》第 10 章 SE(3) 等变）。它为什么不用 GBDT？因为蛋白质数据有丰富的对称性结构值得焊进架构——这是 §11.2.4"数据结构决定方法"的最佳注脚。**想深入，见配套的《蛋白质折叠》课程第 7 章（[`../protein_folding_course/07_alphafold2.md`](../protein_folding_course/07_alphafold2.md)）。**
- **分子 / 蛋白生成（molecular & protein generation）—— 扩散模型**：设计新分子 / 新蛋白，是折叠的"逆问题"。主流用**扩散模型（diffusion model）**（回扣第 10 章）：在结构 / 构象空间里学"从噪声逐步去噪生成合理结构"，常配合几何等变约束。见《蛋白质折叠》第 9 章（[`../protein_folding_course/09_protein_design.md`](../protein_folding_course/09_protein_design.md)）。

> **诚实的边界**：科学应用里"预测得准"不等于"理解了机理"。AlphaFold 能高精度预测静态结构，但它**不直接给出折叠的物理过程、动力学路径、或为何如此折叠的因果机制**；它也在数据稀少的区域（如全新折叠类型、无同源序列的蛋白）可信度下降。机器学习是强大的"模式插值器"，把它当"已经理解了科学"是危险的过度解读——相关 / 预测 ≠ 因果 / 机理（直通 §11.4）。

> **要点**：同一套机器学习方法论横跨视觉 / NLP / 语音 / 推荐 / 时序 / 表格 / 科学，**各领域平级**；每个领域的"主力架构"由其数据结构与对称性（归纳偏置）决定——网格 → CNN、序列 → Transformer、低秩交互 → 嵌入 / 矩阵分解、异构表格 → GBDT、科学结构 → Transformer + 几何深度学习 / 扩散。蛋白质折叠是科学这一类里的旗舰，与其他领域并列、不凌驾。

## §11.4 负责任的 AI

> 这一节是暗线一（泛化的陷阱）在伦理与社会层面的延伸：当一个泛化能力有限、且会放大数据偏差的系统被部署到影响真人的决策里，技术问题就变成了责任问题。本节本身就是本课"诚实气质"的集中体现，请认真对待。

### §11.4.1 分布漂移（distribution shift）

机器学习的所有理论保证（包括泛化）都建立在一个核心假设上：**测试数据与训练数据来自同一分布**（独立同分布，i.i.d.）。现实几乎总会违反它：

把联合分布拆成 $P(\mathbf{x},y)=P(y|\mathbf{x})\,P(\mathbf{x})$，三种漂移恰好对应"动了哪一块"，构成完整三分对照：

- **协变量漂移（covariate shift）**：是 $P(\mathbf{x})$ 改变而 $P(y|\mathbf{x})$ 固定（新用户群、新地区、新设备来了，但"给定输入下标签怎么生成"的规律没变）。
- **标签 / 先验漂移（label / prior shift）**：是 $P(y)$ 改变（疫情期间疾病患病率突变；类别基率变了，但每类的特征长相没变）。
- **概念漂移（concept drift）**：是 $P(y|\mathbf{x})$ 本身改变——输入到输出的映射规律变了（欺诈手法进化、用户偏好随潮流变）。这是最难救的一种，因为模型学到的"道理"本身过时了。

漂移是模型"上线即开始衰老"的根本原因。对策是 §11.1.8 的**监控 + 持续重训**——以及承认"模型在它没见过的分布上不可信"（呼应 §11.1.3 诚实边界）。

> **与数学三课的连接**：所有泛化保证（第 2 章）都默认训练 / 测试**独立同分布（i.i.d.）**，这正是《概率与统计》第 6 章大数定律 / 中心极限定理成立的前提——用训练集上的经验平均去估计总体期望（经验风险逼近真实风险），靠的就是 i.i.d.。分布漂移就是 i.i.d. 假设的破裂：一旦测试分布偏离训练分布，经验风险就不再是真实风险的无偏估计，"训练集上学到的"和"线上要面对的"成了两件事。应对漂移的贝叶斯思路，本质是把新数据当证据做**贝叶斯更新**（《概率与统计》第 8 章）——持续重训就是工程上最朴素的"更新后验"。

### §11.4.2 捷径学习与虚假相关（shortcut learning & spurious correlation）

模型是"懒惰的优化者"：它会抓住**任何**能降低训练损失的相关性，哪怕那是数据采集的伪影而非真实因果。打个比方：一个为了应付考试而抄近路的学生，发现"凡是题干很长的选择题答案多半选 C"，于是不读题直接选 C——在这次模拟卷上得分很高，换一套题立刻原形毕露。模型抄的就是这种"题干长度"式的捷径。经典故事（多为示意性、用以说明机理）：一个"识别狼 vs 哈士奇（husky）"的模型，其实学的是"背景有没有雪"；一个肺炎检测模型，学的是"哪家医院的扫描仪标记"。这些**虚假相关**在训练分布里有效，分布一变就崩，且会带来荒谬甚至有害的决策。

**为什么会这样（机理）？** 经验风险最小化（ERM，第 2 章）只奖励"在训练分布上把损失降下去"，它**不区分**一个相关性是真实因果还是采集伪影——只要"有雪"和"是狼"在训练集里高度共现，用"有雪"做判据就能合法地降低训练损失，而它比"理解狼的形态"更容易学（更低维、更线性可分）。优化器顺着最省力的下坡走，自然先抓住这条捷径。换句话说，捷径学习不是模型"笨"，恰恰是它"太会优化你给的那个目标"——而你给的目标（训练分布上的损失）里，本就分不清因果与巧合。这把问题接回了全章红线**相关 ≠ 因果**：模型学的永远是相关，要它学因果，得靠你在数据 / 目标 / 评估里额外注入结构（多环境数据、分布外测试、因果约束），而不能指望它自己悟出来。

> **常见陷阱（捷径 / 虚假相关）**：高离线指标可能来自模型抄了一条你没想到的捷径。防御靠：**错误分析 + 分群评估 + 用可解释性工具看模型到底在看哪里 + 在分布外（out-of-distribution）数据上测试**。指标好不代表学对了东西。

### §11.4.3 数据偏见与公平性（bias & fairness）

模型从历史数据学习，而**历史数据嵌着历史的偏见**。如果过去的招聘 / 信贷 / 司法决策对某些群体不公，模型会**忠实地学会并放大**这种不公，还披上"算法客观"的外衣。打个比方：用一面只照过去的镜子来决定未来，照出来的当然还是过去的样子——模型不是中立的预言家，而是历史的复读机，且因为它高效、规模化、"看起来客观"，复读得比人更彻底。需要警惕：

- **指标公平性的多重定义**：人口平等（各群体正预测率相等）、机会均等（各群体真阳率相等）、预测值校准（同一个分数在各群体里对应同样的真实阳性概率）等——这些定义**在数学上常常无法同时满足**（不可能性结论），必须结合具体场景做价值权衡，没有纯技术的"正确答案"。
- **分群评估是底线**：整体指标好，可能掩盖对某个群体的系统性伤害（§11.1.7）。

**为什么"不可能定理"成立（一句直觉）？** 关键在于**不同群体的基率（真实阳性比例）往往不同**。可以证明：当两个群体的基率不相等时，"预测值校准"和"各群体真阳率 / 假阳率相等"这两类公平**一般无法同时成立**——你把分数调到对两群都校准，真假阳率就会在两群间出现系统差异；你强行拉平真假阳率，分数对两群的含义又不再一致。直觉上，校准是在"给定分数"的条件下要求一致，而真假阳率是在"给定真实标签"的条件下要求一致，当两群基率不同，这两个条件方向上的约束就互相打架，鱼与熊掌不可兼得。所以"算法公平"没有一个能让所有人都满意的纯数学定义，**选哪种公平本身就是一个价值判断**，必须摆到台面上由人来权衡，而不能假装它是个技术细节。

### §11.4.4 可解释性（interpretability / explainability）

"模型为什么这么判？"在高风险领域（医疗、信贷、司法）不是奢侈品而是刚需。打个比方：解释一个线性模型像读一张明码标价的清单（每个特征的系数就是它的"权重"，一目了然），解释一个深度网络则像让一个凭直觉下棋的高手讲清"你这步到底为什么"——他真实的决策过程分布在千万个连接里，任何一句"因为这里有威胁"都只是事后凑出来的近似说法。手段分两类：

- **内在可解释模型**：线性 / 逻辑回归（看系数）、决策树（看路径）、GBDT 的特征重要性——本身就较透明（呼应第 3、5 章）。
- **事后解释（post-hoc）**：对黑盒模型，用特征归因方法（如基于扰动 / 梯度 / 博弈论分配的归因）解释单次预测看了哪些特征。

**为什么黑盒难解释（机理）？** 难点不在"我们不够聪明"，而在深度模型的决策**本就分布在海量参数的非线性交互里**，没有一个紧凑的"理由"可读。线性模型的预测能精确分解为"各特征贡献之和"（$\hat y=\sum_i w_i x_i$，每项就是一份贡献），所以系数即解释；深度网络的预测是层层非线性复合，特征之间高度纠缠，**根本不存在这样一个忠实的可加分解**。事后解释方法（如基于博弈论的归因）做的事，是用一个**局部的、可加的简单模型去近似**黑盒在某个样本附近的行为——这是逼不得已的近似，所以才会有下面"诚实边界"里说的不忠实、不稳定。可解释性的根本张力（表达力 vs 可解释性）由此而来：越强的表达力往往意味着越纠缠、越难有简洁的"为什么"。

> **诚实的边界**：事后解释是对黑盒的**近似**，本身可能不忠实、不稳定（同一预测换个解释器给不同理由），也容易被误读成因果。"模型说收入是主因"不等于"提高收入就会被批贷"——那是**相关性的归因，不是干预的因果**。可解释性工具帮你建立直觉、抓捷径学习，但别把它当成对模型推理的完整、可靠的真相（再次：相关 ≠ 因果）。

### §11.4.5 隐私（privacy）

模型可能**记住并泄露**训练数据里的敏感信息（成员推断攻击能判断某人是否在训练集里；大模型可能逐字吐出训练文本）。打个比方：一个把课本背得太熟的学生，你随口问一句，他能接出原文的下一句——这说明那句话"在不在他读过的书里"是可以被探出来的。

**成员推断（membership inference）为什么可能（机理）？** 根子在过拟合（暗线一）：模型对**见过的训练样本**往往比对**没见过的样本**拟合得更好——训练样本上的损失更低、预测置信度更高、输出更"笃定"。攻击者正是利用这个系统性差异：拿一个样本喂给模型，看它的损失 / 置信度是否低得"像训练过的"，就能以高于随机的概率判断"这个人是否在训练集里"。所以**泛化差距（训练误差与测试误差的鸿沟）本身就是隐私泄漏的通道**——模型越过拟合，这个通道越宽。这给出一个深刻的联系：**减小过拟合既改善泛化、也改善隐私**，二者同源。对策方向包括差分隐私（differential privacy，给训练注入受控噪声、从数学上限制"单个样本在不在"对输出的影响、提供可证明的隐私保证）、联邦学习（数据不出本地、只传模型更新）等。隐私与精度通常有此消彼长的张力（注入的噪声既挡住攻击者、也模糊了模型），需要权衡。

### §11.4.6 鲁棒性与对抗样本（robustness & adversarial examples）

深度模型可能对**人眼无法察觉的微小扰动**极度脆弱：给图像加一层精心构造、肉眼看不见的噪声，模型就把熊猫高置信度判成长臂猿（gibbon）。**对抗样本（adversarial example）** 揭示了一个深刻事实：模型学到的决策边界和人类的感知边界**根本不是一回事**，它在我们以为"显然一样"的地方有意想不到的裂缝。这在安全敏感场景（自动驾驶、人脸识别、内容审核）是真实威胁，也再次印证暗线一——**模型的"理解"远比它的指标暗示的脆弱**。

**为什么微小扰动能造成大翻转（机理：高维线性性）？** 一个常被引用的解释是：脆弱性主要来自模型在**高维空间里的（近似）线性**，而非它"太复杂、太非线性"。设想模型的某个打分近似 $\mathbf{w}^\top\mathbf{x}$，给输入加一个和 $\mathbf{w}$ 同向、每维都极小（小到肉眼看不见）的扰动 $\boldsymbol{\delta}$，打分的变化是 $\mathbf{w}^\top\boldsymbol{\delta}=\sum_i w_i\delta_i$。**维度 $d$ 极高时（图像有几十万维），哪怕每一维的 $|\delta_i|$ 都微不足道，几十万项同向累加起来也能把打分推过决策边界**——单像素的改动看不见，整幅图协同的改动却足以翻转结论。所以对抗脆弱性不是"模型不够强"的偶然瑕疵，而是高维 + 近似线性几乎必然的结构性后果；攻击者只要沿损失对输入的梯度方向（最快翻转方向）走一小步，就能精准构造出这种扰动。这也解释了为什么对抗样本常能在不同模型间**迁移**——它们利用的是高维线性这一共性，而非某个模型的特殊弱点。

### §11.4.7 能耗与环境成本（energy & environmental cost）

训练超大模型消耗可观的电力与算力，带来碳排放与资源集中问题。"更大更强"并非没有代价。打个比方：用一台数据中心级的超算去做一件本可以用一台笔记本完成的事，不只是浪费电费，更是把本可普惠的能力锁进了少数有钱买算力的机构手里。负责任 AI 也包括**问一句"这个问题真的需要这么大的模型吗"**——很多时候一个小模型 / 经典方法 + 好特征就够了（回扣 §11.2），既省钱又省碳，还更可解释。

**为什么成本不只是钱（机理）？** 这里有三层叠加的代价。其一是**直接能耗与碳排放**：训练 + 长期推理（推理累计起来常比一次训练更耗能）都在持续耗电。其二是**资源集中**：当"更强"高度依赖"更多算力 + 更多数据"，能力就向少数掌握算力的机构集中，加剧不平等、削弱可复现与可监督。其三呼应 §11.1.5 的**复杂度 / 收益比**：很多任务的指标提升对模型规模是**严重递减**的——规模翻十倍可能只换来零点几个点，而能耗、延迟、上线成本、不可解释性的代价却是线性甚至超线性增长的。所以"选多大的模型"从来不是纯技术问题，而是把性能、成本、碳、公平一起摆上台面的权衡——和 §11.1.5 选型、§11.4.3 公平性是同一种"算总账"的思维。

> **实战连接（信贷风控，串起整节）**：一个信贷评分模型——分布漂移（经济周期变、违约模式变）要求持续监控重训；虚假相关（学到"邮编"这个种族 / 收入的代理变量）要靠错误分析与公平审计揪出；公平性（不能对受保护群体系统性拒贷）要分群评估并做价值权衡；可解释性（法规要求给拒贷理由）偏向逻辑回归 / GBDT；隐私（用户财务数据敏感）要合规处理。**这一个真实系统，把本节每个议题都点亮了——负责任 AI 不是附加题，是真实部署的内在要求。**

> **要点**：负责任 AI 的核心难点都根植于"泛化有边界、模型放大数据偏差"：分布漂移让模型上线即衰老、捷径 / 虚假相关让高指标骗人、历史偏见被算法放大并洗白、黑盒难解释且解释本身可能不忠实、模型会泄露隐私、对抗样本暴露脆弱的决策边界、巨型模型有真实环境成本。贯穿一切的红线是**相关 ≠ 因果**，贯穿一切的解药是**诚实地承认模型不知道什么**。

## §11.5 三条暗线总回顾

学了十一章，是时候把三条暗线拧成一股绳，看它们如何在**任何一个**应用里**同时**出现。

**暗线一·泛化（generalization）**：机器学习的中心问题——从有限带噪数据推广到没见过的数据。它在第 2 章正式登场（偏差 - 方差、过拟合）、在第 9 章再攀高峰（深网络泛化之谜、双下降）、在本章 §11.2 化为诊断对策、在 §11.4 化为负责任 AI 的根源（分布漂移、对抗样本都是"泛化失败"的不同面孔）。

**暗线二·表示 + 目标 + 优化（representation + objective + optimization）**：解剖任何方法的"万能解剖刀"。表示 = 假设空间（线性？树？网络？哪种架构？），目标 = 损失（最小二乘 / 交叉熵 / 带不带正则），优化 = 找最优的算法（闭式解 / SGD / EM / 采样）。它从第 1 章登场后贯穿每一章。

**暗线三·归纳偏置（inductive bias）**：没有免费的午餐——任何能泛化的学习都必须对世界做假设。它藏在暗线二"表示"那一格里，在第 5 章（经典方法的偏置对比）、第 8 章（架构 = 焊进去的对称性）集中爆发。

**三者如何咬合**：暗线二是框架，暗线三解释"表示"格里藏的假设、以及为什么必须有假设，暗线一是终极裁判——你选的表示 / 目标 / 优化，最终都用"能不能泛化"打分。下面用两个完整例子把三线串起来：

**例 1·图像分类用 CNN**（视觉）：
- **归纳偏置（暗线三）**：物体平移后还是同一物体（平移等变）+ 局部像素相关性强 → 选卷积，把这两个假设焊进连接模式。
- **表示 + 目标 + 优化（暗线二）**：表示 = 卷积网络（假设空间）；目标 = 交叉熵（= 类别分布 MLE，呼应概率 / 信息论）；优化 = SGD + 反向传播。
- **泛化（暗线一）**：因为偏置和图像真实结构对上了，CNN 用比全连接少得多的参数和数据就泛化得好；但若把它硬套到无空间结构的表格上，强偏置反成束缚、泛化变差——偏置对不对，由泛化打分。
- **若偏置选错会怎样（反例）**：把同一份图像数据改用普通全连接网络（丢掉平移等变 / 局部性这两个偏置），它在小数据上会更难学、更易过拟合、更吃数据——同样的样本量下泛化明显变差。这正说明 CNN 的好不在"层数多"，而在"焊对了假设"：偏置选错（太弱或不匹配），泛化立刻惩罚你。

**例 2·房价预测用岭回归**（表格）：
- **归纳偏置（暗线三）**：假设房价是特征的线性组合 + 系数应当"小而平滑"（不信任过大权重）。
- **表示 + 目标 + 优化（暗线二）**：表示 = 线性函数；目标 = 最小二乘 + L2 正则（= 高斯噪声似然 + 高斯先验的 MAP，概率视角）；优化 = 闭式正规方程 / 梯度下降。
- **泛化（暗线一）**：L2 正则用一点偏差换更小方差（偏差 - 方差权衡），在小数据上比无正则的最小二乘泛化更稳；正则强度 $\lambda$ 由验证集（而非测试集）选——这是暗线一最朴素的操作化。
- **若偏置选错会怎样（反例）**：如果房价与特征其实是强非线性关系（如存在阈值 / 交互效应），那么"线性"这个表示偏置就选错了——再怎么调 $\lambda$ 也只是在错误的假设空间里打转，表现为训练 / 验证误差双高的**欠拟合（高偏差）**。这时该换更有表达力的偏置（GBDT / 加交互项），而不是继续在线性模型上调正则。偏置选错，正则救不了——这是暗线三与暗线一的合演。

> **要点**：三条暗线不是三个孤立的口号，而是**同一件事的三个侧面**，在任何应用里同时在场：你**总在用某个表示 + 目标 + 优化（暗线二）去做学习，其中表示里焊着归纳偏置（暗线三），而这一切的好坏由泛化（暗线一）来最终裁决**。学会在每个新方法 / 新论文里认出这三者，你就拿到了贯穿本课的那把钥匙。

## §11.6 进阶路线图

恭喜你走到这里。本课是"深度入门"——给你一张地图和一套判断力，但每个主题背后都有可以深耕的世界。下面是一份分类的进阶路线。

### §11.6.1 经典教材（按"先广后深"排）

- **Hastie, Tibshirani & Friedman，《The Elements of Statistical Learning》(ESL)**——统计学习的圣经，经典方法（线性 / 树 / 集成 / 核 / 正则）讲得既有统计原理又有几何直觉，呼应本课第 2、3、5 章；其简化版 ISL（带 R/Python 实验）更适合作为起点。
- **Bishop，《Pattern Recognition and Machine Learning》(PRML)**——以**概率视角**统一全书（贝叶斯、图模型、EM、核），是本课"概率视角"暗线的最佳延伸，呼应第 3、6 章与《概率与统计》。
- **Murphy，《Probabilistic Machine Learning》(两卷)**——最现代、最全的概率机器学习教材，从经典一路覆盖到深度与生成模型，几乎是本课全程的"加长加深版"，呼应每一章。
- **Goodfellow, Bengio & Courville，《Deep Learning》**——深度学习的标准底本，呼应第 7、8、9、10 章（成书略早于 Transformer 浪潮，注意力部分需配论文补）。
- **Sutton & Barto，《Reinforcement Learning: An Introduction》**——强化学习的权威入门，呼应第 10 章 RL 部分，把 MDP / 价值 / 策略 / TD 讲得无可替代。

### §11.6.2 公开课与动手资料

- **吴恩达（Andrew Ng）机器学习 / 深度学习系列**——最友好的入门，建立全局直觉，适合配本课第 1–4 章。
- **斯坦福 CS231n（视觉 / CNN）、CS224n（NLP / Transformer）、CS229（机器学习理论）**——分别深耕本课第 8 章视觉、NLP 与第 2、3 章理论。
- **《Dive into Deep Learning》(D2L)**——从零实现 CNN/RNN/注意力 /Transformer，配第 7、8 章动手练习最佳。
- **Kaggle**——真实数据集 + 竞赛 + 公开 notebook，是把本课方法论（§11.1、§11.2）落到手上的最好练兵场，尤其磨炼特征工程与评估纪律。

### §11.6.3 论文精读清单（每条一句话呼应本课哪章）

按主题列代表性方向（用通行说法，细节以原文为准）：

读论文时带着一个问题最有效：**"它解决了前一代的什么痛点？"** 下面每条都标出这个痛点，让你带着问题去读。

- **优化**：Adam（自适应学习率）—— 呼应第 4 章。痛点：朴素 SGD 对学习率敏感、各参数共用一个步长在稀疏 / 不同尺度梯度上低效；Adam 给每个参数自适应步长，让"开箱即用"成为可能。
- **正则 / 训练**：Dropout、BatchNorm、ResNet（残差）—— 呼应第 9 章三大训练支柱。痛点分别是：过拟合（Dropout 用随机失活逼网络别依赖单个神经元）、深层训练时激活分布漂移导致难收敛（BatchNorm 稳住每层输入分布）、网络一深就退化 / 梯度难传（ResNet 用恒等捷径让"加深不变差"）。
- **架构**：LeNet/AlexNet/VGG/ResNet（CNN 演进）、LSTM、Vaswani 等"Attention Is All You Need"（Transformer）、ViT、word2vec（嵌入）、GCN/GAT（图）—— 全面呼应第 8 章，"架构 = 归纳偏置"的论文级证据。代表性痛点：LSTM 解决朴素 RNN 的长程依赖 / 梯度消失；Transformer 解决 RNN 无法并行、长程依赖仍弱的双重痛点（用注意力一步连通任意两位置）；word2vec 解决独热表示无语义、维度爆炸；GNN 解决"如何在不规则图结构上做卷积"。
- **生成模型**：Kingma & Welling 的 VAE、Goodfellow 等的 GAN、Ho 等的 DDPM（扩散）—— 呼应第 10 章，注意三者机制别串。痛点：让"从复杂数据分布里采样新样本"变得可学且可训——VAE 给出可优化的似然下界（ELBO），GAN 绕开难算的似然改用对抗博弈，扩散用"逐步去噪"换来比 GAN 更稳的训练与更高的样本质量。
- **自监督 / 表示学习**：对比学习（如 InfoNCE 思路）、掩码自编码 —— 呼应第 6、10 章与《信息论》第 4 章互信息。痛点：标注昂贵；用数据自身造监督信号（拉近正样本对、推开负样本对 / 还原被遮住的部分）学出好表示，摆脱对人工标签的依赖。
- **大模型 / 基础模型**：GPT 系列的自回归语言建模、BERT 的掩码预训练、缩放规律 —— 呼应第 10 章基础模型范式。痛点：每个任务单独训一个模型代价高、迁移差；改为"一次大规模预训练 + 轻量微调 / 提示适配万般下游"。
- **强化学习**：DQN（深度 Q）、策略梯度 / PPO、RLHF —— 呼应第 10 章 RL 与对齐。痛点：DQN 让 Q-learning 能吃高维感知输入（如像素）且训练更稳；RLHF 解决"如何让模型对齐难以写成显式奖励的人类偏好"。
- **科学应用**：AlphaFold 系列、几何深度学习综述（Bronstein 等）—— 呼应第 8 章与《蛋白质折叠》第 7、8 章。痛点：把序列、空间几何、共进化等结构 / 对称性焊进架构，攻克传统方法久攻不下的结构预测。
- **理论 / 泛化**：双下降、彩票假设等关于"过参数化为何泛化"的探索 —— 呼应第 2、9 章暗线一最前沿。痛点：经典偏差 - 方差图景无法解释"为何超大模型反而泛化更好"，这些工作在重画那张图。

> **诚实的边界**：论文清单是"方向指南"而非"权威书目"——领域演进极快，具体哪篇最该读取决于你的目标与时间点。读论文时永远带上本课的"三件套解剖刀"（它的表示 / 目标 / 优化是什么、焊了什么归纳偏置、泛化证据如何），比记住标题重要得多。

## §11.7 五门课如何配合使用

最后，把你正在学的整套课程拼成一张图。

**五门课的分工**：

```
   三门数学课（地基与语言）                   本课（引擎 / 汇合点）           折叠课（旗舰科学应用）
 ┌──────────────────────────┐
 │ 线性代数：空间/变换/SVD   │ ─┐
 │ 概率统计：推断/MLE/贝叶斯 │ ─┼──►  机器学习与深度学习  ──►  蛋白质折叠 / AlphaFold
 │ 信息论：熵/KL/互信息      │ ─┘     （把语言变成会学习的机器）   （一个具体科学问题的攻克）
 └──────────────────────────┘
```

- **三门数学课是地基与语言**：线代给你"数据 = 向量 / 矩阵、变换 = 矩阵乘、降维 = SVD、等变 = 几何"；概率统计给你"从数据反推规律的推断引擎、MLE = 损失、先验 = 正则、采样 = 生成"；信息论给你"熵 / KL / 互信息这套度量与编码语言、交叉熵 = 损失、压缩 = 学习"。
- **本课是引擎与汇合点**：它把这三套语言**焊接成会从数据中学习的机器**——损失来自概率（MLE）与信息论（交叉熵），优化跑在线代的向量空间里（梯度、矩阵乘、条件数），表示与降维是线代的 SVD/PCA，正则是概率的先验、信息论的 MDL。本课是数学与应用之间的那座桥。
- **折叠课是一个旗舰科学应用**：它展示了当本课的引擎（Transformer + 几何深度学习 + 扩散）开足马力，去攻一个具体而深刻的科学问题（蛋白质结构）时能做到什么。它是本课无数应用里最闪亮的一个，**但和视觉 / NLP / 推荐平级，不是目的地**。

**推荐总闭环**：

1. **下行（建地基）**：从三门数学课打底，把线代 / 概率 / 信息论的关键对象（SVD、MLE、贝叶斯、熵 / KL）变成你的肌肉记忆。
2. **汇合（造引擎）**：进入本课，每学一个 ML 方法就**主动回引**它用到的数学（"这个损失是哪门课的什么对象？这个正则是什么先验？这个降维是哪个分解？"），让地基连接活起来。
3. **上行（看应用）**：用折叠课作为一个完整、深刻的应用实例，验证你"懂引擎"——你应该能在 AlphaFold 里认出本课的注意力、几何等变、端到端训练，以及数学三课的线代几何与概率推断。
4. **回环（再下沉）**：当你在应用里遇到不懂的角落（如等变的群论、贝叶斯的层次模型、率失真与信息瓶颈），再回头到对应数学课深挖。**学习不是一条直线，而是这个上下穿梭的环**——和 §11.1 的流水线一样。

### §11.7.1 结语

这门课从一个最朴素的问题出发——**机器如何从有限的经验里学到能推广的规律**——一路造到了能处理图像、语言、分子的深度系统。如果你只带走三样东西，我希望是：

- **泛化是中心问题**：一切努力，最终都为了"在没见过的数据上表现好"，而不是把训练集背得滚瓜烂熟。
- **三件套是解剖刀**：任何方法 / 论文，都拆成表示 + 目标 + 优化去看，你就不会被术语吓住。
- **归纳偏置是艺术**：没有免费的午餐，机器学习的功夫在于把对世界的假设和问题的真实结构对上——并且**诚实地知道你假设了什么、模型不知道什么**。

带着这三样，加上本章的工程纪律与责任意识，你已经从"会跑模型的人"成为"懂为什么、能判断、能改进、能负责的人"。地图已经在你手上，路要你自己走。

> **要点**：三门数学课是地基与语言、本课是把语言变成会学习机器的引擎与汇合点、折叠课是一个旗舰科学应用；推荐闭环是"下行建地基 → 汇合造引擎（学 ML 时主动回引数学）→ 上行看应用（在 AlphaFold 里认出所学）→ 回环再下沉"。学习是上下穿梭的环，不是直线。

## 本章小结

- **端到端流水线（§11.1）**：问题定义 → 数据 → 特征 / 表示 → 模型与基线 → 训练 → 评估 → 部署 → 监控 / 迭代，是一个**环**。核心信条：**数据与问题定义通常比模型更决定成败**；数据泄漏与训练 / 服务不一致是头号实战杀手；上线只是另一个起点（MLOps）。
- **实战智慧（§11.2）**：先建强基线（逻辑回归 / GBDT）；调试从数据 / 标签 / 泄漏查起，用"能否过拟合一小撮"区分 bug 与泛化；指标按业务代价选（准确率在不平衡时骗人，看精确率 / 召回 /F1/AUC/PR-AUC，回归看 MAE/MSE/$R^2$）；经典 vs 深度由**数据结构与归纳偏置是否对得上**决定；过拟合 / 欠拟合靠训练 - 验证误差关系诊断，但"参数多必过拟合"被**双下降**证伪。
- **跨领域巡礼（§11.3）**：视觉 / NLP / 语音 / 推荐 / 时序 / 表格 / 科学**平级**，主力架构由数据结构的对称性决定；蛋白质折叠（AlphaFold = Transformer + 几何深度学习、分子生成 = 扩散）是科学这一类的旗舰，指向《蛋白质折叠》课程。
- **负责任的 AI（§11.4）**：分布漂移、捷径 / 虚假相关、数据偏见与公平、可解释性、隐私、对抗样本、能耗——都根植于"泛化有边界、模型放大数据偏差"，红线是**相关 ≠ 因果**，解药是诚实承认模型不知道什么。
- **三条暗线总回顾（§11.5）**：泛化是中心问题与终极裁判、表示 + 目标 + 优化是万能解剖刀、归纳偏置是结构即先验的艺术——三者在任何应用里同时在场。
- **路线图与五课配合（§11.6、§11.7）**：教材 / 公开课 / 论文 / 项目阶梯 / 时间表；三门数学课（地基）→ 本课（引擎汇合点）→ 折叠课（旗舰应用），推荐"下行 - 汇合 - 上行 - 回环"的学习闭环。

三条暗线在本章彻底合流并收束：**泛化（暗线一）从第 2 章的中心问题，长成了 §11.2 的诊断对策与 §11.4 的责任根源；表示 + 目标 + 优化（暗线二）从第 1 章的解剖刀，成了 §11.3 看懂任何应用、§11.6 读懂任何论文的钥匙；归纳偏置（暗线三）从第 8 章的架构高潮，落地为 §11.2.4「数据结构决定方法」的实战判据。** 你带走的不该是一堆算法名字，而是这三条能解剖一切机器学习的暗线，加上一套诚实、负责、能判断的工程心智。

## 动手与思考练习

**练习 11.1（思考·数据泄漏）** 一个团队预测信用卡欺诈，离线 AUC 高达 0.999，上线后却几乎抓不到欺诈。请列出至少三种可能的数据泄漏来源，并说明各自如何造成"离线虚高、上线崩盘"。

*参考答案*：(1) **标签 / 未来信息泄漏**：特征里混进了"该交易事后是否被退款 / 被冻结"等只有事发后才知道的字段——它几乎等价于标签。(2) **预处理泄漏**：在划分训练 / 测试**之前**用全体数据做了标准化 / 特征选择 / 目标编码，测试集统计量偷偷进了训练。(3) **时间泄漏**：随机打乱划分而非按时间切，于是用"未来的交易"训练去预测"过去"，现实里不可能。(4) **重复 / 分组泄漏**：同一用户的多笔交易被分到训练和测试两边，模型记住了用户而非学到欺诈模式。*延伸思考*：用 sklearn `Pipeline` + `TimeSeriesSplit` 如何分别堵住第 (2) 和第 (3) 种泄漏？

**练习 11.2（思考·指标选择）** 某罕见病患病率 1%，模型 A 准确率 99%（永远预测"没病"），模型 B 准确率 95% 但召回率 90%。哪个更有用？请用混淆矩阵和精确率 / 召回 /F1 论证，并说明该用什么指标汇报。

*参考答案*：模型 A 准确率虽高却**召回率为 0**（漏掉所有病人），毫无医用价值——这正是准确率在类别不平衡时的陷阱。模型 B 召回 90% 抓住了绝大多数病人，对筛查（漏报代价远高于误报）有用。该汇报**召回率、精确率、F1、PR-AUC**，并结合"漏一个病人 vs 误报一次复检"的真实代价定阈值；只报准确率是误导。*延伸思考*：若这是癌症初筛（后面还有确诊环节），你会把工作点偏向高召回还是高精确率？为什么？

**练习 11.3（动手·编程·评估）** 用 sklearn 在一个不平衡分类数据上，构造一个 `Pipeline`（标准化 + 逻辑回归），用分层交叉验证（`StratifiedKFold`）评估，输出准确率、精确率、召回、F1、ROC-AUC、PR-AUC，并画出 PR 曲线。

*参考答案要点*：
```python
from sklearn.pipeline import Pipeline
from sklearn.preprocessing import StandardScaler
from sklearn.linear_model import LogisticRegression
from sklearn.model_selection import cross_validate, StratifiedKFold
from sklearn.metrics import (precision_recall_curve, average_precision_score)
pipe = Pipeline([("sc", StandardScaler()),
                 ("clf", LogisticRegression(class_weight="balanced", max_iter=1000))])
cv = StratifiedKFold(n_splits=5, shuffle=True, random_state=0)
scoring = ["accuracy","precision","recall","f1","roc_auc","average_precision"]
res = cross_validate(pipe, X, y, cv=cv, scoring=scoring)
for k in scoring: print(k, res["test_"+k].mean())
```
关键点：**标准化放进 Pipeline**，让缩放参数只在每折训练子集上拟合（防泄漏，呼应 §11.1.3）；用分层折保持类别比例；不平衡时重点看 `average_precision`（PR-AUC）。*延伸思考*：把 `class_weight="balanced"` 去掉，观察召回率如何变化——你看到了什么权衡？

**练习 11.4（思考·经典 vs 深度）** 你拿到一个 8 万行、40 列（数值 + 类别混合）的客户流失表格数据。同事坚持"用深度学习才高级"。请用归纳偏置的语言论证为什么你会**先**上 GBDT，并说明什么情况下你才考虑深度模型。

*参考答案*：表格数据的列之间没有空间 / 时序 / 图结构，深度架构的平移等变 / 局部性等强偏置在这里**无用甚至有害**（假设了不存在的对称性）；而 GBDT 的"轴对齐分段常数"偏置恰好契合表格里"某特征超阈值则如何"的逻辑，且省工程、好调、自带特征重要性（可解释，呼应风控需求）。先上 GBDT 是因为它在这类数据上样本效率、稳定性、上线速度俱佳（§11.2.4）。只有当数据量极大、且存在可被深度模型利用的结构（如含文本 / 序列 / 图字段），或要做多模态融合时，才值得上深度模型。*延伸思考*：如果这 40 列里有一列是"用户最近 50 条操作日志的文本"，你的方案会怎么变？（提示：可用预训练语言模型抽该列的嵌入，再喂给 GBDT——混合架构。）

**练习 11.5（动手·编程·捷径学习排查）** 构造一个"埋了捷径"的数据集：在一个二分类数据里**人为加一列与标签强相关的伪特征**（如 `leak = y + 小噪声`，模拟采集伪影 / 泄漏代理变量），训练一个模型，然后用**置换重要性（permutation importance）**或 SHAP 排查它是否依赖了这条捷径。观察去掉该列后性能如何崩塌，呼应 §11.4.2。

*参考答案要点*：
```python
import numpy as np
from sklearn.ensemble import RandomForestClassifier
from sklearn.inspection import permutation_importance
from sklearn.model_selection import train_test_split
# 真特征 X_real（信号弱），再拼一列与 y 几乎一致的伪特征 leak
leak = (y + np.random.normal(0, 0.1, size=y.shape) > 0.5).astype(float)
X = np.column_stack([X_real, leak])
Xtr, Xte, ytr, yte = train_test_split(X, y, random_state=0)
clf = RandomForestClassifier(random_state=0).fit(Xtr, ytr)
imp = permutation_importance(clf, Xte, yte, n_repeats=20, random_state=0)
print(imp.importances_mean)   # 最后一维（leak）重要性应远高于其余
```
关键点：置换重要性把某一列**打乱**后看指标掉多少——掉得越多说明模型越依赖它。你会看到 `leak` 列的重要性一骑绝尘，这就是"模型抄了捷径"的指纹；而在**分布外**（把 `leak` 与 $y$ 的相关性去掉或反转）测试时，模型会立刻崩盘。这正是 §11.4.2 防御组合"可解释性工具 + 分布外测试"的微缩实操。*延伸思考*：置换重要性在**特征高度相关**时会失真（打乱一列时它的相关搭档仍泄露信息），为什么？这对你解读重要性意味着什么？（提示：相关特征会"互相打掩护"，单独打乱低估其真实作用。）

**练习 11.6（思考·三件套解剖刀）** 任选第 10 章的一个生成模型（VAE / GAN / 扩散之一），用暗线二（表示 + 目标 + 优化）拆解它，并指出它焊进了什么归纳偏置（暗线三）、如何用泛化（暗线一）评判它。

*参考答案要点*（以 VAE 为例）：**表示** = 编码器 + 解码器神经网络，假设数据由低维潜变量 $z$ 经解码生成（低维流形假设 = 归纳偏置）；**目标** = ELBO = 重构项 $-$ KL 正则项（= 对数似然下界，KL 把 $q(z|x)$ 拉向先验 $p(z)$，是信息瓶颈 / 正则，呼应《信息论》第 4、9 章）；**优化** = 重参数化技巧让梯度可传 + SGD。**归纳偏置**：低维潜空间 + 通常的高斯先验，假设数据"本质维度低、且潜空间光滑连续"。**泛化评判**：看它在留出数据上的似然 / 重构、以及生成样本的多样性与真实度（生成模型的"泛化"是能否生成训练集没有但合理的新样本，而非死记训练样本）。*延伸思考*：GAN 的"目标"为什么不是似然而是 min-max 博弈？这让它的"泛化"该怎么衡量更微妙？

**练习 11.7（思考·负责任 AI · 模型审计）** 设计一个最小的"模型审计清单"（至少 5 条），用于在一个影响真人的高风险模型（如招聘筛简历）上线前做检查，每条对应 §11.4 的一个议题。

*参考答案要点*：(1) **分群评估**：按性别 / 年龄 / 地域分别看指标，确认无某群体系统性劣化（公平性）。(2) **捷径 / 虚假相关排查**：用特征重要性 / 解释工具看模型是否依赖了敏感属性的代理变量（如毕业院校→社会经济地位），并做错误分析。(3) **分布外测试**：在与训练分布不同的样本上测，评估鲁棒性与漂移风险。(4) **可解释性**：能否对每个拒绝给出可理解理由（法规 / 信任需求）。(5) **隐私合规**：训练数据是否含敏感信息、是否需脱敏 / 差分隐私。(6) **上线后监控计划**：定义要监控的输入 / 预测分布与重训触发条件。*延伸思考*：为什么"删掉性别这一列"通常**不足以**保证公平？（提示：其他特征可能是性别的代理变量，模型仍可间接学到——这也是相关性的隐蔽之处。）

**练习 11.8（动手·编程·端到端微缩版）** 选一个公开表格数据集，完整走一遍微缩流水线：划分（防泄漏）→ 建平凡基线（多数类 / 均值）与简单基线（逻辑回归 / GBDT）→ 在验证集调一两个超参 → 在**从未动过的**测试集报告恰当指标 → 做一次错误分析（人工看 20 个错样本归类）。提交一段说明"复杂模型相对基线的真实增益是多少"。

*参考答案要点*：重点不在分数高低，而在**纪律**：测试集全程不参与任何决策（§11.1.7）；先有平凡基线给分母（§11.2.1）；调参只用验证集（第 2 章）；指标按任务 / 不平衡选（§11.2.3）；错误分析常能发现标签噪声或一类系统性错误（§11.1.7）。能清楚说出"GBDT 相对'永远猜均值 / 多数类'提升了多少、相对逻辑回归提升了多少、这点提升值不值这点复杂度"，就达到了本练习目的。*延伸思考*：如果复杂模型只比简单基线高 0.3% 但慢 10 倍、不可解释，你上哪个？为什么这是个工程而非纯技术决策？

**练习 11.9（思考·五课闭环）** 用一句话各说出：在 AlphaFold（折叠课第 7 章）里，你能认出本课的哪个对象、《线性代数》的哪个对象、《概率与统计》或《信息论》的哪个对象？

*参考答案要点*：**本课**——注意力 / Transformer（第 8 章）+ 端到端训练（第 9 章）+ 几何深度学习的等变归纳偏置（第 8 章，暗线三）。**线性代数**——三维旋转 / 平移的 SE(3) 等变与刚体变换（《线性代数》第 10 章），以及处处的矩阵乘 / 内积相似度。**概率 / 信息论**——共进化信号的统计学习、训练损失里的（交叉熵 / 似然）目标（《概率与统计》第 7 章 MLE、《信息论》第 3、4 章）。*延伸思考*：这个练习其实在验证你"懂引擎"——若你能在任意一个新应用里都做这样的"三线 + 三课"认领，你就真正把五门课打通了。
